# 장치·모듈 배선 웹앱 개발 계획 초안

작성일: 2026-08-21  
참고 서비스: [EasyCable](https://easycable.co.kr/)

## 1. 제품 목표

사용자가 실제 부품 사진이나 이미지를 등록하고 단자 위치를 표시한 뒤, 부품 간 배선을 시각적으로 작성할 수 있게 한다. 도면 데이터로부터 BOM과 배선 리스트를 자동 생성하고, 작업 파일·CSV·PNG·PDF로 보관하거나 전달할 수 있어야 한다.

참고 서비스의 현재 공개 화면을 기준으로 기능을 분석했다. 동일한 사용자 문제와 작업 흐름을 구현하되, 상표·문구·디자인·소스 코드를 복제하지 않고 독자적인 UI와 데이터 구조로 개발한다.

## 2. 확인된 참고 기능

### 프로젝트와 편집기

- 새 작업, 열기, 저장, 다른 이름으로 저장, 최근 작업, 이전 버전 복구
- 여러 배선도 시트의 생성, 복제, 이름 변경, 정렬, 삭제
- SVG 도면, 그리드와 스냅, 확대/축소와 패닝
- 선택/이동, 배선, 배선 라벨, 주석 텍스트 모드
- 실행 취소/다시 실행, 키보드 단축키와 단축키 설정
- 미연결 단자 시각적 점검

### 부품과 단자

- 이미지로 부품 추가 및 재사용 가능한 부품 라이브러리
- 라이브러리 폴더, 검색, 가져오기/내보내기
- 이미지 배경 제거, 자르기, 회전, 배치 크기 조정
- 부품 단자 추가·이동·삭제·다중 선택·정렬·균등 배치
- 단자 이름, 색상 프리셋과 라벨 방향 설정

### 배선과 산출물

- 단자 간 배선, 직선/직각 라우팅
- 배선 색상 팔레트와 의미, 굵기, AWG 등의 속성
- 자동 BOM과 배선 리스트, 표시 열과 사용자 정의 행/열
- BOM/배선 리스트 CSV, 도면 PNG, 인쇄/PDF 내보내기
- 프로젝트명, 작성일, 비고, 출력 워터마크/범례

### 보존과 서비스 기능

- 브라우저 자동 저장, 문서별 최근 작업, 주기적 스냅샷
- 샘플 프로젝트, 한국어/영어, 설정
- 계정, 무료/유료 등급, 피드백과 출시 알림 기능의 확장 여지

## 3. 권장 기술 스택

| 영역 | 권장 기술 | 선택 이유 |
|---|---|---|
| 프런트엔드 | React 19, TypeScript, Vite | 편집기 UI의 복잡한 상태를 컴포넌트화하고 빠르게 개발하기 좋음 |
| 도면 렌더링 | SVG + Pointer Events | 단자·배선 hit-test, 인쇄, 벡터 출력, DOM 접근성이 쉬움. MVP 규모에 적합 |
| 상태 관리 | Zustand + Immer | 캔버스 상태를 명시적으로 갱신하고 명령 기반 undo/redo를 구성하기 쉬움 |
| 로컬 저장 | IndexedDB + Dexie | 큰 이미지 Blob과 프로젝트 스냅샷을 localStorage보다 안정적으로 저장 |
| 검증/마이그레이션 | Zod | 저장 파일 입력 검증과 프로젝트 스키마 버전 업그레이드에 유용 |
| 스타일/UI | CSS Modules 또는 Tailwind CSS, Radix UI | 편집기 전용 레이아웃과 접근 가능한 모달·메뉴 구현 |
| 이미지 처리 | Canvas API, createImageBitmap, Web Worker | 자르기·회전·배경제거 작업이 UI를 막지 않게 처리 |
| 내보내기 | 브라우저 Print CSS, jsPDF/pdf-lib, SVG→Canvas | PDF, PNG, CSV 산출물 지원 |
| 백엔드(2단계) | Supabase(PostgreSQL, Auth, Storage) | 로그인, 클라우드 동기화, 이미지 저장, 공유 기능을 빠르게 추가 가능 |
| 테스트 | Vitest, Testing Library, Playwright | 모델 단위 테스트와 실제 포인터 조작 E2E를 모두 검증 |
| 품질/배포 | ESLint, Prettier, GitHub Actions, Cloudflare Pages/Vercel | 정적 MVP 배포와 PR 단위 품질 검사 구성이 간단 |
| 관측성 | Sentry, 익명 이벤트 분석(PostHog 등) | 편집기 오류와 사용 흐름을 개인정보 최소 수집 원칙으로 파악 |

### 기술 선택 메모

React Flow는 노드 기반 플로차트에는 좋지만 부품 이미지 위 임의 단자, 도면 출력, 세밀한 배선 편집에는 제약이 생기기 쉽다. MVP는 직접 만든 SVG 편집 레이어가 더 적합하다. 수천 개 객체에서 성능 문제가 실제로 측정될 때 Konva/PixiJS나 OffscreenCanvas를 검토한다.

처음부터 서버를 필수로 두지 않는다. 로컬 우선(local-first) 구조로 핵심 편집 경험을 먼저 완성하고, 계정·동기화·공유가 필요해질 때 Supabase를 추가하면 초기 비용과 장애 지점을 줄일 수 있다.

## 4. 제안 아키텍처

```text
UI shell (toolbar / library / inspector / tabs)
             |
Editor commands (add, move, wire, delete, undo, redo)
             |
Project domain model ---- derived BOM / wire list
       |                         |
SVG renderer                CSV/PDF/PNG exporters
       |
IndexedDB repository --- optional cloud sync adapter
```

핵심 원칙은 화면 요소가 상태를 직접 수정하지 않고 `Command`를 발생시키게 하는 것이다. 각 명령에 정방향·역방향 변경을 기록하면 undo/redo, 자동 저장, 추후 협업 로그를 같은 기반 위에서 만들 수 있다.

## 5. 핵심 데이터 모델

```ts
type Project = {
  schemaVersion: number;
  id: string;
  name: string;
  createdAt: string;
  updatedAt: string;
  sheets: Sheet[];
  componentDefinitions: ComponentDefinition[];
  palette: WireColor[];
};

type ComponentDefinition = {
  id: string;
  name: string;
  manufacturer?: string;
  partNumber?: string;
  imageAssetId: string;
  width: number;
  height: number;
  terminals: TerminalDefinition[]; // 이미지 기준 0..1 정규화 좌표
  bom?: { specification?: string; unitPrice?: number; links?: string[] };
};

type Sheet = {
  id: string;
  name: string;
  componentInstances: ComponentInstance[];
  wires: Wire[];
  annotations: Annotation[];
};

type Wire = {
  id: string;
  from: TerminalRef;
  to: TerminalRef;
  colorId: string;
  gauge?: string;
  label?: string;
  routing: "straight" | "orthogonal";
  waypoints: Point[];
};
```

이미지는 JSON에 base64로 반복 삽입하지 않고 별도 자산 저장소에 두며, 저장 파일을 단일 파일로 제공할 때는 ZIP 컨테이너(`project.json` + `assets/*`) 형식을 권장한다. 단자 좌표를 이미지 크기에 대한 정규화 값으로 저장하면 이미지 리사이즈에도 위치가 유지된다.

## 6. 개발 범위와 우선순위

### MVP — 실제 배선도 한 장을 완성할 수 있는 수준

1. 프로젝트/시트 모델과 SVG 캔버스
2. 부품 이미지 업로드, 배치, 선택, 이동, 크기 조정, 삭제
3. 단자 생성·이름·위치 편집
4. 단자 간 직선/직각 배선, 색·굵기·라벨 속성
5. 그리드, 스냅, 줌, 패닝, 다중 선택, undo/redo
6. IndexedDB 자동 저장, JSON/ZIP 가져오기·내보내기
7. BOM과 배선 리스트 자동 계산, CSV 내보내기
8. PNG와 인쇄용 PDF, 기본 미연결 검사

### Beta — 반복 작업과 안정성 개선

- 폴더·검색·프리셋을 갖춘 부품 라이브러리
- 이미지 자르기·회전·간단한 배경 제거
- 시트 복제·정렬, 최근 작업과 스냅샷 복구
- 배선 수동 경유점, 겹침 가독성, 자동 번호 부여
- 프로젝트 스키마 마이그레이션, 손상 파일 복구 안내
- 다국어, 단축키 설정, 접근성, 모바일/태블릿 열람 최적화

### 이후 버전 — 서비스화

- Google/OIDC 로그인, 클라우드 동기화, 공유 링크와 권한
- 조직 부품 라이브러리, 템플릿, 감사 이력
- 실시간 공동 편집은 수요 검증 후 CRDT(Yjs) 기반으로 별도 설계
- 전기 규칙 검사(전압, 전류, 극성, 중복 연결)는 도메인 규칙 엔진으로 분리
- 요금제, 사용량 제한, 관리자·피드백 기능

## 7. 단계별 일정 초안

2명(프런트엔드 중심 1명, 풀스택/QA 1명), 주 5일 기준 약 10~12주 초안이다. 1명이라면 16~20주를 현실적인 범위로 본다.

| 단계 | 기간 | 주요 결과물 | 완료 기준 |
|---|---:|---|---|
| 0. 발견/설계 | 1주 | 사용자 시나리오, 와이어프레임, 스키마, 기술 스파이크 | 대표 도면 3종과 성능 목표 확정 |
| 1. 편집기 기반 | 2주 | 앱 셸, SVG 좌표계, 선택/이동/줌, 명령 이력 | 포인터/키보드 조작 E2E 통과 |
| 2. 부품/단자 | 2주 | 이미지 자산, 부품 배치, 단자 편집기 | 재사용 부품을 등록하고 배치 가능 |
| 3. 배선 | 2주 | 연결, 라우팅, 속성, 라벨, 미연결 검사 | 실제 예제 도면을 오류 없이 재현 |
| 4. 저장/산출물 | 2주 | 자동 저장, 파일 I/O, BOM, 배선표, CSV/PNG/PDF | 새 브라우저에서 파일 복원 및 출력 일치 |
| 5. 안정화 | 2주 | 복구, 접근성, 성능, 오류 처리, 베타 피드백 | 회귀 E2E와 목표 브라우저 점검 통과 |
| 6. 배포 | 1주 | 운영 배포, 모니터링, 개인정보 문서 | 장애 대응·백업 절차와 릴리스 체크 완료 |

## 8. 주요 사용자 시나리오와 인수 조건

### 새 부품을 배선도에 사용

사용자가 이미지를 업로드하고 이름을 정한 뒤 이미지 위에 `VCC`, `GND`, `SIGNAL` 단자를 배치한다. 라이브러리에 저장된 부품을 시트에 두 번 배치해도 하나의 정의와 두 개의 인스턴스로 관리되어야 한다.

### 배선을 생성하고 수정

사용자가 서로 다른 부품의 단자를 차례로 선택하면 배선이 생긴다. 색, 굵기, 규격, 라벨, 라우팅을 수정할 수 있으며 부품 이동 후에도 끝점이 단자에 붙어 있어야 한다. 삭제와 속성 변경은 undo/redo가 가능해야 한다.

### 결과물을 전달

BOM은 같은 부품 정의의 인스턴스를 수량으로 집계한다. 배선 리스트는 각 배선의 시작 부품/단자와 도착 부품/단자, 색상, 규격, 라벨을 포함한다. 저장한 프로젝트를 다른 브라우저에서 열었을 때 이미지와 단자·배선 위치가 동일해야 한다.

## 9. 비기능 요구사항

- Chrome/Edge 최신 2개 버전을 우선 지원하고 Safari/Firefox는 베타에서 검증
- 200개 부품, 2,000개 단자, 1,000개 배선에서 드래그 중 목표 45fps 이상
- 5초 내 자동 저장, 비정상 종료 후 마지막 성공 스냅샷 복구
- 외부 파일은 MIME, 크기, 이미지 디코딩을 검증하고 HTML/SVG 스크립트를 실행하지 않음
- 로컬 데이터 삭제, 클라우드 저장 여부, 분석 수집을 사용자에게 명확히 표시
- 색상만으로 연결 의미를 전달하지 않고 라벨·선 스타일을 함께 제공

## 10. 위험 요소와 대응

| 위험 | 대응 |
|---|---|
| 직각 배선 자동 라우팅의 난이도 증가 | MVP는 단순 L/Z 경로와 수동 경유점으로 제한; 장애물 회피는 후속 |
| 이미지가 프로젝트 용량을 급증시킴 | 업로드 시 리사이즈/WebP 변환, 해시 중복 제거, 자산 별도 저장 |
| undo/redo와 자동 저장 상태 불일치 | 명령 경계와 저장 스냅샷 경계를 테스트로 고정 |
| PDF가 브라우저별로 달라짐 | 고정 페이지 모델과 인쇄 전용 렌더러, 골든 이미지 테스트 사용 |
| 참고 서비스와의 IP 혼동 | 기능 요구만 참고하고 명칭, 아이콘, 레이아웃, 소스와 브랜드는 독자 설계 |
| 모바일 편집 UX 저하 | MVP는 데스크톱 편집 중심, 모바일은 열람/간단 수정 범위로 명시 |

## 11. 구현 착수 전 결정할 항목

1. 주요 사용자가 제어반·산업장비 작업자인지, 메이커/교육 사용자인지
2. 오프라인 전용 MVP인지, 첫 출시부터 로그인·동기화가 필요한지

5. 부품 라이브러리를 개인·조직 중 어느 단위로 공유할지
