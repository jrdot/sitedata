## 1. 목적

같은 대상을 문서마다 다르게 부르거나, 한 단어를 여러 뜻으로 쓰면 개발 단계에서 요구 사항을 잘못 읽고 데이터 모델·API·테스트가 어긋난다. 이 문서는 개발에 들어가기 전에 **대상 하나에 이름 하나**를 정해 그런 오류를 줄인다.

---

## 2. 사용 규칙

1. **표준 용어만 쓴다.** 3장의 "쓰지 않는 표기"는 새 문서·이슈·커밋에 쓰지 않는다.
2. **한정어 없이 쓰지 않는 단어가 있다.** `라벨`, `라이브러리`, `주석`, `탭`, `페이지`, `분석`, `버전`은 4장의 규칙대로 한정어를 붙인다. 여러 종류를 한꺼번에 가리킬 때만 예외다(예: 영역 이름 "배선·라벨·주석").
3. **수량·한도·저장의 단위는 `프로젝트` 또는 `시트`로만 적는다.** `도면`, `문서`, `작업`, `페이지`는 단위로 쓰지 않는다.
4. **참고 서비스의 화면 문구는 따옴표로 인용한다.** 예: 참고 서비스의 "새 작업" 메뉴. 신규 웹앱의 UI 문구는 이 문서의 범위가 아니며 별도로 설계한다.
5. **식별자는 3장의 "식별자" 열을 따른다.** 이 열은 [개발 계획 초안](<../../data/ezcable v1/docs/development-plan.md>) 5장의 데이터 모델을 기준으로 하고, 거기에 없는 것은 `(안)`으로 표시했다. `(안)`은 데이터 모델을 확정할 때 함께 확정한다.
6. **참고 서비스의 식별자는 그대로 옮기지 않는다.** `component`, `label`, `ortho`처럼 뜻이 다르거나 겹치는 것이 있다(5장).
7. **띄어쓰기:** 동작을 나타내는 말은 띄어 쓴다. `자동 저장`, `실행 취소`, `다시 실행`.
8. **새 용어 등록:** 문서에 새 개념이 나오면 먼저 이 문서에 행을 추가하고 변경 이력에 남긴다.

## 4. 뜻이 여럿인 단어

아래 단어는 문서에서 서로 다른 뜻으로 쓰였다. 오른쪽 규칙대로 구분한다.

| 단어 | 발견된 뜻 | 규칙 |
|---|---|---|
| 프로젝트 | ① 사용자의 작업 단위 ② 신규 웹앱 개발 | ①만 `프로젝트`. ②는 `개발 프로젝트` |
| 도면 | ① 프로젝트 전체 ② 시트 한 장 ③ 캔버스 ④ 그려진 내용 | ④로만 쓴다. ①은 `프로젝트`, ②는 `시트`, ③은 `캔버스` |
| 문서 | ① 프로젝트 ② 사양서 같은 개발 문서 | ②로만 쓴다 |
| 페이지 | ① 시트 ② 웹 페이지 ③ PDF 쪽 | ①은 `시트`. ②는 `요금제 페이지`처럼 이름을 붙이고, ③은 `인쇄 페이지` |
| 라벨 | ① 배선 라벨 ② 단자 라벨 ③ 색 의미 ④ 프리셋 이름 | 한정어 없이 쓰지 않는다. ③④는 `라벨`이라 부르지 않는다 |
| 주석 | ① 도면 주석 ② 코드 주석 | 항상 한정어를 붙인다 |
| 굵기 | ① 화면의 선 굵기 ② 전선 규격(AWG) | ①만 `굵기`. ②는 `규격` |
| 스냅샷 | ① 복구용 저장본 ② 실행 취소용 상태 복사본 | ①만 `스냅샷`. ②는 `실행 취소 이력` |

## 6. 결정이 필요한 항목

아래는 이 문서에서 한쪽을 골라 적용했지만, 프로젝트 담당자가 확정해야 하는 항목이다.

| # | 항목 | 적용한 안 | 다른 안 | 판단 근거 |
|---|---|---|---|---|
| T-01 | 배선 표의 이름 | 배선 리스트 | 결선표 | 개발 계획 초안과 README가 "배선 리스트"를 쓴다. "결선표"는 참고 서비스 v2의 문구다 |
| T-02 | 부품의 식별자 | `ComponentDefinition` / `ComponentInstance` | `Part` / `PartInstance` | 개발 계획 초안을 따랐다. React의 Component와 이름이 겹치는 것을 피하려면 `Part` 쪽이 낫다 |
| T-03 | 기능 목록의 `우선순위` 열 | 그대로 둠 | `릴리스 단계`로 변경 | STD-001 6.1이 이 열에 `MVP / Beta / 이후`를 적도록 한다. 내용은 우선순위가 아니라 릴리스 단계다 |
| T-04 | `(안)` 표시 식별자 | 제안만 함 | 데이터 모델 확정 때 결정 | 개발 계획 초안 5장에 없는 이름이다 |
| T-05 | 프로젝트 파일을 읽고 쓰는 동작의 이름 | 열기 / 저장 | 가져오기 / 내보내기 | 참고 사양서를 따랐다. 개발 계획 초안과 README는 "JSON 가져오기·내보내기"로 적었고, 이 표기는 고치지 않았다. 파일을 직접 덮어쓰는 방식인지에 따라 정한다 |
| T-06 | 신규 웹앱의 이름 | 정하지 않음 | — | `data/ezcable v1/README.md`의 제목이 "EZCable 웹앱"이고 수집본 폴더 이름도 `ezcable v1`·`ezcable v2`여서 참고 서비스(EasyCable)와 혼동된다. 개발 계획 초안 1장은 상표를 복제하지 않는다고 적었다 |
