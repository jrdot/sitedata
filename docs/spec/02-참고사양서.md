## 0. 문서 규칙

### 0.1 작성 원칙

- **확인된 기능 + 한 줄 설명 + 원본 위치**만 기록한다. 상세 동작은 위치를 따라가 원본에서 확인한다.
- 이 문서는 참고 서비스의 "무엇"을 정리한 것이다. 신규 앱의 "어떻게"(UI·코드·문구)는 별도로 설계한다.

### 0.2 기능 분류 — 업무 분장

ID = **접두어(업무 분장) 1글자 + 계층별 2자리 번호 3개** (형식은 0.3 참고)

| 접두어 | 업무 분장 | 범위 |
|---|---|---|
| **F** | Frontend | 화면, 편집기 상호작용, 클라이언트 로직 |
| **B** | Backend | 인증, 이용권 판정, 주문·결제, 서버 API |
| **D** | Database | 도메인 데이터 모델, 브라우저 저장소, 파일 형식, 서버 테이블 |
| **I** | Infra·운영 | 호스팅·배포, 기능 스위치, 보안 설정, 분석·모니터링, 품질 검증 |
| **C** | Content·정책 | 법적 문서, 요금 정책, 안내 문구, 샘플·예제 데이터, 마케팅 미디어 |

### 0.3 계층 관리

**형식:** `X00-00-00` = 접두어 1글자 + 계층별 2자리 번호 3개 + 하이픈 구분자

| 계층 | 형식 | 예 | 의미 |
|---|---|---|---|
| 1계층 | `X01-00-00` ~ `X99-00-00` | F05-00-00 | 대분류(영역) |
| 2계층 | `X01-01-00` ~ `X01-99-00` | F05-01-00 | 중분류(기능 묶음) |
| 3계층 | `X01-01-01` ~ `X01-01-99` | F05-01-01 | 개별 기능 |

- 각 계층은 01~99까지 쓴다. `00`은 "그 계층이 없음(상위 항목 자체)"을 뜻한다.
- 두 자리를 고정해 문자열 정렬 순서와 계층 순서가 일치한다.

### 0.4 ID 표기 규칙

| 사용처 | 규칙 | 예 (F05-01-02 분기 배선) |
|---|---|---|
| **파일 내부** (본문·표·연관 열·커밋 메시지·이슈) | 항상 **전체 ID** | `F05-01-02` |
| **파일명** | 상위 계층은 폴더가 나타내므로 **자기 계층 번호만** + 이름 | `F05-배선/01-배선생성/02-분기배선.md` |

- 파일명 규칙은 기능별 문서를 폴더로 나눌 때 적용한다. 폴더명도 같은 규칙을 따른다(1계층 폴더만 접두어 포함: `F05-배선`).
- 파일명에서 ID를 찾을 때는 폴더 경로를 이어 붙인다: `F05` + `01` + `02` → `F05-01-02`

### 0.5 ID 운영 규칙

- 한 기능이 여러 분장에 걸치면 분장별로 ID를 따로 붙이고 **연관** 열로 연결한다. 예: 결제 = F09-03-02(화면) ↔ B03-01-01·B03-02-02(서버) ↔ D06-01-01(테이블)
- 한번 부여한 ID는 바꾸지 않는다. 폐기된 기능은 상태를 ○로 두고 번호를 재사용하지 않는다.
- v0.1의 ID는 [부록 A](#부록-a-구-id--신-id-대응표)에서 찾을 수 있다.

### 0.6 위치 표기

| 별칭 | 실제 경로 |

| `V1/` | `ezcable v1/data/easycable/` |
| `V2/` | `ezcable v2/easycable.co.kr/` |
| `V1/index` | `V1/index.html` (v1 편집기) |

`파일:행`은 해당 행 또는 구획의 시작 행이다.

### 0.7 상태 표기

| 기호 | 의미 |
